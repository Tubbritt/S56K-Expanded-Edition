## Changes from V1.1

1. **Fixed recording stops despite free sample RAM.** After several captures, the sampler could have plenty of total free RAM but too little immediately available recording workspace. Auto Sample now waits for background sample-memory cleanup and, when needed, requests Akai's native memory organisation. It checks the available recording space again before arming the recorder.
2. **Added a controlled retry for the recording-memory error.** If the specific native memory error occurs, Auto Sample cleans up the recorder before attempting recovery and one retry. Other recording errors still stop the run and show the problem.
3. **Improved cancellation and timeout handling during memory recovery.** A new recording cannot start while its memory cleanup remains unfinished. Completed samples are retained. A cleanup failure that requires a restart remains visible instead of permitting another unsafe start.
4. **Added clearer progress messages.** **WAITING FOR SAMPLE MEMORY** and **ORGANISING SAMPLE MEMORY** explain pauses between recordings. These operations can take time; the next recording waits for them to finish.
5. **Added recovery information for troubleshooting.** Recovery counters and the recording-failure diagnostic screen help distinguish a workspace-recovery problem from genuinely insufficient sample RAM. If a run stops, include a photo of the complete screen in your report.
6. **Corrected the misleading cropping message.** With **CROP AFTER LOOP OFF**, finalising a recording no longer incorrectly appears as cropping after the loop. This is a status-label correction; it does not change the underlying sample processing.
7. **Updated the edition labels.** Both model paths display **EXPANDED EDITION V1.2**, and the diagnostic title identifies V1.2. The underlying Akai OS/settings/protocol identity remains **2.14**.

The release-tail preservation, loop playback mode, monitoring and crossfade improvements introduced in [V1.1](v1.1.md) remain in place.

## Practical notes

- Completed programs and samples stay in RAM. Use the normal **SAVE** page to save them with their samples.
- A full sampler can still run out of recording space. Memory organisation makes existing free space usable; it does not add sample RAM or discard completed captures.
- Long stereo recordings require substantial memory. For example, 68 recordings of 18 seconds at 44.1 kHz stereo use about **206 MiB**, before temporary recording or processing workspace.
- V1.2 reserves **8 KiB more CPU RAM than V1.1**. Installed sample RAM capacity is unchanged.
- Close the Editor, ak.Sys and other sampler-control applications while Auto Sample is running.
- A normal summary can show recovery counters. A **LAST LOOP** review message may occupy that footer instead. Photograph any error screen and report the recovery messages you observed.
